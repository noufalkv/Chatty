Chatty Backend Deployment Guide

Step-by-step instructions for deploying the Chatty backend on AWS using Terraform, CI/CD, and custom scripts.

  1. Configure CircleCI: Edit .circleci/config.yml to define jobs for build, test, deploy. Example job: 
    jobs:
  2. Initialize Terraform: In the deployment folder, run: 
    terraform init
    This sets up providers and remote state.
  3. Environment Variables: Add AWS credentials, CodeDeploy settings, CodeCov token, Slack webhook, etc. in CircleCI project settings.
  4. Workflow: Define workflow to run jobs in sequence (build → test → deploy). Use filters for branches (e.g., only deploy on develop).
  5. Notifications: Integrate Slack for build/deploy notifications. See README.md for setup.
  6. Variable Prefix: Replace <variable-prefix> in config.yml with your Terraform prefix value.
  • Plan & Apply: Preview changes with terraform plan, then apply with: 
    terraform apply -auto-approve
    Resources will be created in AWS. Monitor progress in the terminal and AWS Console.
  • Destroy: To remove all resources: 
    terraform destroy

    Troubleshooting: If builds fail, check CircleCI job logs, ensure environment variables are set, and verify AWS permissions.
  • Remote State: deployment/3-main.tf configures S3 backend for state sharing. This is essential for team collaboration.
  • File Map: Each .tf file manages a specific AWS resource. See table below for details.

    • AWS Setup

    1. Create an AWS Account: Sign up at aws.amazon.com and enable billing.
    2. IAM User & CLI: Create an IAM user with programmatic access. Attach policies for EC2, S3, CodeDeploy, and Route53. Download credentials and run aws configure locally: 
      aws configure
    3. Domain & Route53: Register a domain (e.g., via Namecheap, GoDaddy). In AWS Route53, create a hosted zone for your domain. Copy the NS records to your domain provider's dashboard.
    4. S3 Bucket for Env Files & Terraform State: Create an S3 bucket (e.g., chatty-deploy-env) for storing environment files and remote Terraform state. Add a subfolder (e.g., develop).
    5. Environment Variables: Prepare a .env file based on .env.development.example. Zip and upload to S3 for use in EC2 user-data scripts.
    Reference: See README.md for screenshots and step-by-step instructions.
    Best Practice: Use separate IAM users for automation and personal access. Enable MFA for security.

    Deployment Scripts

    • scripts/before_install.sh: Prepares the environment before installation.
    • scripts/after_install.sh: Runs post-installation tasks.
    • scripts/application_start.sh: Starts the application after deployment.
    
  # Example: before_install.sh
  #!/bin/bash
  sudo yum update -y
